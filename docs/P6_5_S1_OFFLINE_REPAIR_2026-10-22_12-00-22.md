## 3. 新引用规则

新实验请求版本为 `p65_s1_semantics_v4_tools5`；回答 JSON 协议为 `p65_s1_answer_v1`，顶层为 schema_version、citations、claims。

- tool_call 引用具有唯一 id、真实 call_id、tool、完整实际 arguments；可选 observation_id 若非 null，必须与记录匹配。不能把 p63 ID 填进 call_id 或 Runtime observation_id。
- 每个工具引用分别列 outer_status、captured_status、historical_evidence_id、source、originals 路径数组、captured_at、evaluated_at 和 event_window。缺失字段为 null，originals 为空数组；无需逐个打印原件哈希。
- input_context 通过 input_path 键/下标数组引用初始 user JSON，不带工具 call_id。known_gaps 只证明输入提供了该声明，不能证明模型成功读取日志。
- 实际 Provider 输入没有 Runtime observation_id，自动版本探针也没有暴露其真实 call_id；提示词允许 observation_id=null，由离线报告从持久化记录关联。自动探针通过输入背景引用，不要求模型猜造隐藏标识。
- claims 每项有 id、text、kind、refs 和 use；kind 区分 fact、hypothesis、limitation。field_value 另提供相对引用值的 field_path 和 value，检查的是精确字段关系。
- 一个引用可供多项陈述复用；重复定义引用 id、重复工具 call_id、重复 claim id、重复同项引用均给出问题。重要陈述不能靠一份未被使用的引用清单取得表面合规。

有效引用链为：`本轮真实 call_id + tool/arguments → record → Runtime observation_id → result → 历史 p63 ID/source/originals`。输入背景另走 `初始 user JSON → input_path`，不伪装工具归因。

event_window 是实际日志请求的 start/end，**并不证明取得窗口内日志**。离线展开结果还保留 replay_collected_at 与历史 query_started_at/query_finished_at。实际日志事件正文、counter 含义和指标回看窗口仍需结合原始字段审查，不能统一改称采集瞬间。

## 4. 确定性检查及其边界

`review_answer(answer, records, input_context)` 检查格式、真实调用身份、工具名、参数、Runtime observation_id、历史来源与状态/时间字段的一致性，并核对声明的字段值。

- log_content 被标为 fact 时，须有真实 query_logs 引用、历史 captured_result.status=ok 和非空日志正文；范围拒绝不能满足条件。输入背景也不能证明本轮成功读取。
- valid_zero 被标为 fact 时，须为历史 ok 的 query_metrics 数值零；no_data、缺值和布尔 false 不满足。外层 no_data 不会抹掉历史内层 ok 的有效零。
- 本历史调查中，fault_count 事实声明不能由累计 counter 或未关联日志建立；根因、修复、当前健康和当前恢复也没有已验证的事实基础。相应用途若标为 fact，会输出问题，不写回业务状态。
- 自然语言可能与 kind/use/字段声明不一致；即使声明正确，整句话也可能偏题、扩大范围或引入无依据因果。这些情况统一输出“需要语义审查”。测试特意放入“数据库根因已确认且当前业务已经恢复”但 use=observation 的文本，证明结构通过仍不自动可信。

原始旧格式回答的扫描只识别明确的 `call ` 加反引号标识这类引用语法，不依据“冻结”“恢复”等关键词判断事实。它报告的“缺少新结构”是迁移提示，**不是倒推旧 TASK 当时已经要求 JSON**。原回答本身的确定性错误是那三处 p63/call 身份混用。

检查结果始终为 offline_advisory_only，带答案哈希、问题位置、关联来源和语义复核事项。复用 ResultTrust 只读投影：有问题可投影 rejected，合法结构仍为 pending_review；trusted 永远 false、human_approval=not_recorded。没有 accepted 写入或任何人工审批操作。CLI 正常退出仅表示审查报告已生成。

## 5. 原件及持久化复核

固定样本读取先校验已锚定的运行 manifest 和全部封印文件，再核对两轮 body SHA、raw/integrity/SDK/completion、首轮输出原样进入第二轮、四组 call/output/name/arguments/result 绑定、发出前 pending=[] 和 Checkpoint SHA、最终 records 与原回答。
