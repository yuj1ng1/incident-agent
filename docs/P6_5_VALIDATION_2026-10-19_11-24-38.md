### Responses 多轮输入的必要处理

生产 Worker 仍然保持 `provider_verified=False` 的 B 证据重建。P6.4 仅验证过该策略的工程传递，未证明真实 Provider 收到了完整 function_call_output 协议链。

P6.5 适配器因此明确负责本次**协议探测请求的输入投影**：首轮发送冻结的最小历史上下文及已提交自动版本探针；后续发送上一轮实际请求历史、原始 response.output，以及从当前已提交 Checkpoint.history 读出的实际 function_call_output。发送前逐项核对 call_id、name、arguments、原记录 result；缓存结果绑定 trace 中的 observation_id。未提交、缺失或被篡改的输出不能被补成成功结果。生产 B 上下文没有被冒称为已通过 Provider 认证的完整链。

这意味着实际 SDK body 由实验适配器进行受控投影，并不等同于生产 Worker 的 B 输入原样透传。原 Worker 输入对应的 Checkpoint、阶段、提交事件与实际 SDK 请求分别保留，不能据本次 Mock 把生产 `provider_verified` 改为 true。

离线中断恢复沿用 Manager.recover / claim / fencing；丢弃的未完成协议调用不会补造 function_call_output，已保存工具记录以明确的历史数据进入恢复上下文。付费入口 `max_resumes=0`，只执行一次 Worker.run_once，不进行自动恢复或补跑。

## 3. 协议资料与已知兼容性风险

[OpenAI 官方函数调用说明](https://developers.openai.com/api/docs/guides/function-calling)规定通过 function_call 的 JSON 参数调用函数，并用相同 call_id 返回 function_call_output。本地 ModelClient 仍使用 SDK `responses.create`，实际 SDK 适配器使用同一 Responses 创建操作的 `with_raw_response.create` 变体保存返回原文。

[DeepSeek 官方 Responses 兼容说明](https://api-docs.deepseek.com/guides/responses_api/)列出 functions、function_call/function_call_output 支持，同时不支持 previous_response_id；客户端须携带历史。文档还说明 parallel_tool_calls 与 max_tool_calls 不生效。因此本次不依赖服务端限制工具次数，工具白名单和执行上限由 Python/Runtime 保证。**官方文档不是当前账号及本机 SDK 的实际联调结果。**

本地 SDK over MockTransport 已实际验证标准多轮序列化、原始返回及解析；同时验证 HTTP 400、超时、非法 JSON、不完整状态及 usage 缺字段时只进入一次 SDK、停止且不重试。P6.3 已记录的 `cache_write_tokens` 缺失风险仍存在：若真实 Provider 返回同样结构，本实现会保存原文和 SDK 序列化并严格失败，不手工补字段、不宣称兼容成功。

本次使用现有 valid_chain 的保守规则：工具调用尚未配对时插入 message/reasoning 等不满足该规则的序列会停止，不重排原 response.output 来制造通过。这仍是待真实返回验证的兼容性限制。模型别名若返回了与批准模型不一致的名称，也会保留返回并停止。

## 4. 工具白名单与历史证据范围

仅允许 `order-service` 的以下工具；没有实时 HTTP transport。

| 工具 | 实际范围 |
| --- | --- |
| query_metrics | 精确匹配已冻结 metric 参数：http_5xx_rate、http_requests_total、http_request_rate、http_latency_p95_seconds、service_scrape_up。其他指标返回明确 no_data；额外非法参数由 Worker 拒绝。 |
| query_logs | 省略时间时回放唯一已批准的冻结日志采集窗口；显式时间须与原参数精确一致。其他窗口返回 outside_approved_frozen_evidence，不查询当前 Loki。 |
| get_running_version | 回放已冻结版本结果；原 commit 未知，保留 no_data/commit_unknown，不以当前仓库 HEAD 补齐。自动探针亦计入总工具上限。 |

历史封套保留 `captured_at`、原来源、原 result、原件路径/哈希、P6.3 最小投影、故障窗口、采集窗口；固定 `historical_only=true`、`use_for_current_state=false`、`evidence_scope=time_window`。外层 status=no_data 明确表示无法回答当前状态；内层 captured_result.status 保留原采集的 ok/no_data 区别及有效 0.0，没有用回放时刻更新原采样时间。Runtime 的新 collected_at 只记录本次回放读取。

本地原件复核确认 http_request_rate 的原始结果为 ok / 0.0，5xx/P95 的原始结果为 no_data，二者没有合并。有效历史观测仍不能成为当前健康证据。冻结日志中 Loki 纳秒时间、正文秒级事件时间和延后的查询范围均保留，不能把查询窗内视为精确故障窗内。

初始 Incident 仅用于驱动 Runtime，明确为 synthetic_alert_input。实验未读取当前 /alerts，也没有捕获新的 order-service firing；隔离 Incident 的内部 firing 字段不构成真实告警证明。没有发送 /order、/error、/health、/version、Prometheus 或 Loki 的新服务请求，没有更改任何 Demo 开关或启动待恢复服务。

### 输入脱敏及哈希

首轮只发送可复核的最小历史上下文，不外发 `.env`、数据库行、整个工作区、用户当前 Prompt、运行日志或真实凭据。工具响应来自已核验的固定原件及 P6.3 允许字段投影。每轮创建 SDK 请求前执行相同的敏感字段/值检查、实际凭据值检查和大小上限，保存完整 body、UTC、SHA-256、Session 预约和 Checkpoint 摘要；不在检查后再改写 body。动态轮次若出现敏感内容，停止外发，不重写输出以伪装原始协议。

允许字段投影是主要控制，模式/凭据值扫描是补充，不能声称能识别任意自然语言中的所有秘密。API 原文保留解码文本及哈希；若 Provider 回显实际 API 凭据，只保存脱敏文本并记录原解码文本哈希和 redacted 标记，停止调查，不把改写后的返回当有效原答继续运行。
